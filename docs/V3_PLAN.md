## 1. Summary

- **v2 today.** A Next.js 14.2.15 App Router site: 8 pages, 5 API routes, 37 components, 6 library files. Worth keeping as patterns: the git-backed content model, the rule that an unknown block renders nothing, the twelve-tab admin and most of its editors, the connection-status panel, the no-flash theme script, and the inline brand icons. Nearly every public component is replaced, because the design brief refuses most of what they do and the seed needs fields v2 cannot store.
- **The seed is ready.** It passes all 40 public patterns when they are matched against string values, as the rules file specifies. Every proof and link in it resolves, all 15 media files it names exist with exact case, and its five empty covers are empty on purpose. The schema must treat the empty `settings.heroModel`, which has no `kind`, as "no model" (D-03).
- **Most handoff targets hold today.** Next.js 16.4.6, React 19.3.1 with stable View Transitions, `ensureStatic`, Tailwind CSS 4.3.5, `motion` 14.14.0, and the Motion+ install method all check out against their own documentation, and every public package in the proposed set resolves in an npm dry run (925 packages, no errors).
- **Where today's tools differ from the handoff.** TypeScript moves from 5.9.3 to 6.0.3, not 7.0.2 (D-72). The repository upload path tops out near 4 MB, not 10 MB (D-23). Lighthouse cannot score SEO 100 on a preview URL or measure Interaction to Next Paint (D-80). Word files cannot be rendered safely in the site's own origin (D-28). KTX2 textures and in-browser STEP conversion need code evaluation that the planned policy forbids (D-81). The sky's 220 kB budget is tight (R-05).
- **Two urgent items sit outside the build.** A cleanup described in the owner's Phase 0 report (Q-01), and a decision on whether production gets a Next.js patch before v3 ships (Q-02).
- **Size.** Revision 2 roughly doubles the build: the sky, the 3D model hero, and nine viewers with in-browser conversion. The phase plan in section 14 of the architecture still fits; Phases 3 and 5 are now the largest.

### 11.5 Phase 6: the admin

`ARCHITECTURE.md` 7 and 11, with the media library of 13A. Everything the v2 admin did stays; the code is new.

- **Shape.** Every route, request schema, and response type is in `lib/admin/contract.ts`. The browser edits through one store (`components/admin/state/`): immutable edits, undo and redo for the session (typing in one field is one step), and changed files found by comparing each file's text with its stored text, so an untouched file is never rewritten and a save sends only changed files. Content files keep the seed's format (two-space JSON, no trailing newline), key order, and empty strings. The twelve tabs, the project list and full-page editor, the block editor for all 21 block types (two columns recursive, unknown types kept as they are), and the media fields sit in `components/admin/{tabs,projects,media}/`; the shell, the save bar, the dialogs, the status panel, and the warning list in `components/admin/shell/`.
- **Draft, preview, publish (D-17 to D-20, Q-30).** A save is one commit on `GITHUB_DRAFT_BRANCH` through the Git Data API (`lib/admin/server/repo.ts`). Before each write the draft is created from the published branch, fast-forwarded to it when it holds nothing unpublished, or has the published branch merged in (a conflict is refused with a plain message). Each save carries a SHA-256 fingerprint of every file as the editor loaded it, and any file it writes that changed on the draft since then (another window, a discard, a merge) is refused with a conflict, so nothing is overwritten unseen; files that changed elsewhere are reported for a reload. A save the content check refuses writes nothing: the checks run before the draft is prepared, again after a merge, and a merge that then fails is put back. The save bar shows the draft's preview address and its build state. Publish lists every changed file, Blob changes, and the build state, then fast-forwards `GITHUB_BRANCH` to the head the owner confirmed; it refuses a diverged draft (with "Bring the draft up to date"), a preview build that has not started, is running, failed, or was canceled, and `main` anywhere but the production deployment. Discard sends the draft head it showed and is refused when the draft moved. "Revert this file to published" loads the published file into the editor. Local development without GitHub variables writes to disk. After a save, the save bar follows the preview build of the draft's newest commit that holds the save (`/api/status` lists the draft's unpublished commits, so a stale or foreign head is never shown as ready) and ends with a sentence saying why when no build finishes. The status panel shows write access only where GitHub's answer proves it, and a GitHub refusal names the call and the permission GitHub asks for (`x-accepted-github-permissions`).
- **Content check on every save (D-19, D-76).** The server checks the whole content as it will be after the save: schema, slug and file name, the public rules, `CONTENT_BLOCKLIST` (fail-closed on Vercel and in CI), media addresses, the GPA and phone copies, and proofs; a hit refuses the save with the rule id, the file, and the field path, and the admin goes to the field. A proof that leads to no visible page fails the check (5.7); the editor's warning list flags it first. `check:content` now also runs in `prebuild`, so a draft that fails it cannot build or be published.
- **Security (11, D-36 to D-42).** No fallback credentials (503 and a setup notice). Constant-time password check (HMAC digests). Sessions are signed tokens with an eight-hour life, bound to the password, in an httpOnly, Secure, SameSite=Strict cookie, with logout. The lockout (five wrong passwords in ten minutes, then ten minutes) counts per address taken from `x-real-ip`, which Vercel sets, in Vercel Runtime Cache, shared by the function's instances in a region; attempts from one address run one at a time, and the status panel names the store in use. A Vercel Firewall rate-limit rule on `POST /api/auth` sits in front, staged in log mode at the owner's request. Every mutating route checks the Origin header and Sec-Fetch-Site and reads its body only as JSON (or multipart for uploads) through a zod schema. Saves write only content paths; uploads only `public/media/<folder>/` with a cleaned name and the type read from the bytes.
- **Headers (D-35, D-81).** One static policy for the site without `unsafe-eval` (`wasm-unsafe-eval` for the viewers' decoders), an admin variant that adds the Blob upload API, and their own policies for the STEP worker (the only place code evaluation is allowed), the sandboxed Word frame, the admin's media stream, and SVG under `/media`. HSTS, nosniff, a referrer policy, X-Frame-Options, a restrictive Permissions-Policy. A browser sweep of every route found no violation. `check:secrets --build` (in `postbuild`) fails the build when a secret value, a private term, or a token shape reaches the build output; it matches private terms as whole words, by the content check's own rule, and notes a term found only inside longer words. `check:content` also scans the admin's own source (its TypeScript, and the scripts under `public/admin-workers/` and `public/viewers/`) for private terms, except `lib/lint.ts`, which holds the rule. Browser bundles alias `ndarray-pixels` to a stub (D-81), so no page code evaluates strings.
- **Media (13A, D-23 to D-30).** One library per project plus the site's, with drag and drop of many files, a progress bar per file, and preparation in the browser: photos to WebP at most 2560 px with their metadata gone (HEIC through libheif-js only when needed), MOV re-wrapped to MP4 with a poster frame, WAV to AAC with a waveform, PDF with a first-page poster and its text, DOCX text, and every 3D format (STEP included, in its own worker, capped at 50 MB and 120 s) to one Meshopt-compressed GLB with its triangle count, part names, and a poster. Names, document text, and part names go through the content check before upload. Files up to 4,000,000 bytes are committed to the draft; larger ones go from the browser to Vercel Blob with a ticket bound to a fixed pathname, type, and size, and a confirm step that checks the bytes (and, for a model, every name in it). Single use is held by the pathname itself: the token never overwrites, and a refused or freshly deleted upload is replaced by a small placeholder rather than deleted, so its pathname cannot be written again (instead of D-26's used-nonce store, which a site without a database cannot keep). The server sanitizes SVG (DOMPurify on jsdom) and strips WebP and PNG metadata. Rename and Replace rewrite references, found by one set of rules for the server and the browser (`lib/admin/references.ts`: any string field, bullets items included, and absolute addresses on the site's own host); a file the draft (or, for Blob, the published site) still uses cannot be deleted. A project's media folder is where its files live, so a renamed project keeps it; Settings, Media holds the site's library and the folders of renamed or deleted projects. OpenDocument files are accepted as downloads; old binary `.doc`, `.xls`, and `.ppt` files are refused with a pointer to the modern formats. The admin-only LGPL code is listed in `licenses/ADMIN-NOTICES.md`. A Blob upload is watched in the browser (`components/admin/media/manager.ts`): a single upload's body is paced so its progress follows what the request has taken, and the upload stops with a plain message when it does not start in 30 s, makes no progress for 90 s, gets no answer within 5 minutes of its last bytes, or is refused again after a whole send (a private store answers 503, which `@vercel/blob` would otherwise retry for half an hour).
